PART 0 — BLOCKERS OUTSIDE PLAY CONSOLE
--------------------------------------------------------------------------------
[BLOCKER] Server reachable from the internet
  pdf-studio-auth.laxmi.solutions and pdf-studio-api.laxmi.solutions resolve to the home
  IP, but port 443 is refused from outside. Fix the router's port-forward (443 and 80 ->
  192.168.1.2) or use a Cloudflare Tunnel. Without this the app cannot sign in or run any
  tool, and Play's RTDN and AdMob callbacks cannot reach the server.

[BLOCKER] Release build
  Ship a new AAB that includes the auth URL fix (/api/v1 on authBaseUrl, commit de156f7)
  and bump the versionCode.

PART 1 — IN-APP BILLING (CREDIT PACKS)
--------------------------------------------------------------------------------
The app and backend already implement billing. Remaining setup:

1. Payments profile
   Play Console -> Setup -> Payments profile. Create or link one (merchant account) so
   you can sell in-app products.

2. Upload a build that contains billing
   The in_app_purchase plugin adds com.android.vending.BILLING automatically. Upload an AAB
   to Testing -> Internal testing. In-app products can only be created once such a build
   exists.

3. Create in-app products
   Monetize -> Products -> In-app products -> Create product. IDs must match EXACTLY:

     Product ID            Name            Description                         Price (INR)
     pdfcraft_credits_10   10 Credits      10 credits to use PDF Craft tools   Rs 49
     pdfcraft_credits_30   30 Credits      30 credits to use PDF Craft tools   Rs 129
     pdfcraft_credits_60   60 Credits      60 credits to use PDF Craft tools   Rs 229

   - Set the prices, let Play auto-convert them for other countries, then ACTIVATE each
     product.
   - They are consumables: the app consumes them only after the server credits the account.

4. License testers
   Setup -> License testing: add tester Gmail accounts, response "RESPOND_NORMALLY". Testers
   buy with test cards and are not charged. Also add them to the Internal testing track's
   tester list.

5. Service account for purchase verification (Google Cloud)
   a. console.cloud.google.com: create or pick a project.
   b. APIs & Services -> Enable "Google Play Android Developer API".
   c. IAM & Admin -> Service accounts -> Create. Then Keys -> Add key -> JSON, and download it.
   d. Play Console -> Users and permissions -> Invite new users -> enter the service account
      email. App permissions for PDF Craft: "View financial data, orders, and cancellation
      survey responses" and "Manage orders and subscriptions". Allow up to 24h to propagate.
   e. Homelab server:
        - copy the JSON to e.g. /etc/pdf-studio/play-service-account.json (chmod 600)
        - in /etc/pdf-studio/prod.env set:
            PLAY_SERVICE_ACCOUNT_KEY_PATH=/app/secrets/play-service-account.json
            PLAY_PACKAGE_NAME=com.vi5hnu.pdf_craft
        - [BLOCKER] docker-compose.homelab.yml only mounts the logs folder. Add a read-only
          volume under pdf-studio-service -> volumes:
            - /etc/pdf-studio/play-service-account.json:/app/secrets/play-service-account.json:ro
        - restart:  sudo systemctl restart pdf-studio.service

6. Real-time developer notifications (refund/void clawback)
   a. Google Cloud -> Pub/Sub -> Create topic, e.g. "play-billing".
   b. Topic -> Permissions -> Add principal
        google-play-developer-notifications@system.gserviceaccount.com  role "Pub/Sub Publisher".
   c. Create a subscription on the topic:
        Delivery type: Push
        Endpoint: https://pdf-studio-api.laxmi.solutions/api/v1/credits/play-rtdn?secret=<LONG_RANDOM_SECRET>
        Recommended: enable authentication (OIDC) with a service account; audience = the
        endpoint URL.
   d. prod.env:
        PLAY_RTDN_SECRET=<LONG_RANDOM_SECRET>
        PLAY_RTDN_AUDIENCE=<endpoint URL, if OIDC is enabled>
        PLAY_RTDN_SERVICE_ACCOUNT=<push service account email, if OIDC is enabled>
   e. Play Console -> Monetize -> Monetization setup -> Real-time developer notifications:
      topic name = projects/<project-id>/topics/play-billing. Save, then "Send test
      notification".

7. Test end to end on the internal track
   Install from the Play testing link using a tester account -> Credits -> buy 10 credits ->
   balance increases. Refund the order in Order management -> the credits are revoked via
   RTDN.

PART 2 — ADMOB (ADS + REWARDED CREDITS)
--------------------------------------------------------------------------------
1. apps.admob.com: link the AdMob app to the Play listing (App settings -> App store
   details) after it is published.
2. Banner, interstitial and app-open units already exist (lib/utils/AdUnits.dart).
3. Rewarded ("Watch an ad" for credits), optional:
   a. AdMob -> Ad units -> Rewarded -> create, reward item "credits", amount 2.
   b. Unit -> Advanced -> Server-side verification -> callback URL:
        https://pdf-studio-api.laxmi.solutions/api/v1/credits/admob-ssv
   c. Paste the unit id into _prodRewarded in lib/utils/AdUnits.dart and rebuild. Until
      then the app hides "Watch an ad".

   under Apps -> app-ads.txt, and set the developer website in the Play listing to
   https://laxmi.solutions.

   (TagForChildDirectedTreatment.yes). If the target audience is adults (recommended,
   Part 4), remove or unspecify this tag. Child-directed ads earn much less and imply
   Families policy obligations.

   18 and over (or 13+). Not designed for children. See the ads note in Part 2.5.

6. News app: No.  Government app: No.  Financial features: No.  Health: No.

7. Advertising ID
   Yes, it's used for advertising (the AdMob SDK declares AD_ID).

8. Data safety form (answer to match the app and backend):
   Collection and security:
     - Encrypted in transit:        Yes (HTTPS)
     - Users can request deletion:  Yes (Account -> Delete account; also via the privacy
                                    policy contact)
   Data types:
     - Personal info -> Email address, Name (optional)
         Collected, not shared. Purpose: Account management. Optional (guest use needs none).
     - Personal info -> User IDs (account/guest id)
         Collected, not shared. Purpose: App functionality, Account management.
     - Financial info -> Purchase history
         Collected, not shared. Purpose: App functionality (credit packs).
     - Files and docs
         Collected; processed ephemerally ("processed only in memory / not stored") IF the
         server truly deletes files after processing, which the Settings privacy text
         promises. Purpose: App functionality. Not shared.
     - Device or other IDs (Advertising ID)
         Collected and shared with the ads provider (Google AdMob).
         Purpose: Advertising or marketing, Analytics, Fraud prevention.
     - App activity / diagnostics
         Declare whatever the AdMob SDK collects per Google's AdMob data disclosure guide.
   Google Drive: files are uploaded or downloaded only at the user's request, directly
   between the device and the user's own Drive. Declare it if the form asks about files.

9. Permissions declarations
   - MANAGE_EXTERNAL_STORAGE ("All files access") needs the Permissions declaration form.
     Suggested justification (core use case "File management"):
       "PDF Craft is a document manager and PDF toolkit. Its core feature is a built-in
        file browser that lets users browse all folders on their device, find PDFs and
        images anywhere in storage, and rename, copy, move and delete them, and save tool
        output alongside the originals. This cannot be achieved with the Storage Access
        Framework or MediaStore because users manage documents across arbitrary folders."
     [RISK] Play often rejects this for PDF tools. If rejected, switch to the system file
     picker (SAF) + MediaStore; this is already on the audit list.
   - Google Drive scopes: drive.readonly is a RESTRICTED scope and needs OAuth app
     verification in Google Cloud (OAuth consent screen -> publish + verification). Using
     only drive.file avoids restricted-scope verification.
